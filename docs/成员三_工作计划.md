# 成员三：行程规划、预算校验与动态调整 —— 工作计划

## 职责总览

| 维度 | 内容 |
|------|------|
| **核心职责** | 行程规划、预算核算、规则校验、自动调整、局部重规划、版本对比 |
| **前端区域** | 时间轴、预算统计、校验结果、自动调整提示、修改前后对比 |

---

## 一、功能清单

### 后端（Python）

| # | 功能 | 说明 |
|---|------|------|
| 1 | **1~3 日行程规划** | 接收候选地点和路线，生成初始行程，必去景点优先安排，景点/餐厅/酒店时间组合，酒店作为每日出发和返回锚点，餐饮时段插入，路线耗时写入时间轴 |
| 2 | **预算计算** | 分别核算酒店（单价×晚数）、门票（单价×人数）、餐饮（人均×人数）、交通四类费用 |
| 3 | **确定性规则检查** | 9 项规则由 Python 代码检查（**不能靠大模型**）：开放时间、时间冲突、路线时间、预算、必去景点、重复地点、步行限制、饮食禁忌、每日结束时间 |
| 4 | **自动调整** | 校验不通过时自动调整一次（仅一次，避免死循环） |
| 5 | **局部重规划** | 用户主动修改后，只修改受影响日期/时段，锁定未受影响部分 |
| 6 | **版本管理** | 每次修改生成新版本，不覆盖旧版本；提供版本列表和版本差异对比 |

### 前端（Vue 组件）

| # | 组件 | 说明 |
|---|------|------|
| 1 | `TripTimeline.vue` | 行程时间轴可视化 |
| 2 | `BudgetPanel.vue` | 预算统计图表展示 |
| 3 | `TripDiff.vue` | 修改前后对比展示 |

## 四、上下游依赖关系

```
输入（依赖别人）                   你（成员三）                     输出（给别人）
────────────────────────────────────────────────────────────────────────────
成员一 → TravelRequest      →   行程规划 + 预算 + 校验   →   Itinerary         → 成员一、前端
成员二 → Place[]            →   自动调整 + 局部重规划    →   BudgetSummary      → 前端
成员二 → RouteResult[]      →   版本管理 + 差异对比      →   EvaluationResult   → 成员一、前端
                                                         →   TripDiff           → 成员一、前端
```

### 数据流

```
新建行程：
  成员一输出 TravelRequest → 成员二输出 Place[] 和 RouteResult[] → 你输出 Itinerary 和 EvaluationResult → 成员一统一组织响应

修改行程：
  成员一识别修改意图 → 你确定需要替换的行程位置 → 成员二提供新地点和路线 → 你局部重规划并重新检查 → 成员一返回修改结果
```

## 五、9 项确定性规则校验

> ⚠️ 这些**必须用 Python 代码**实现，不能依赖大模型判断。

| 错误码 | 规则 | 严重程度 |
|--------|------|----------|
| `PLACE_CLOSED` | 景点/餐厅在游览时段是否开放 | error |
| `ARRIVAL_OUTSIDE_OPENING_HOURS` | 到达时间是否在开放时间内 | error |
| `TIME_CONFLICT` | 前后行程项时间是否冲突 | error |
| `ROUTE_TIME_INSUFFICIENT` | 路线耗时是否超出相邻项间隔 | error |
| `BUDGET_EXCEEDED` | 总费用是否超预算 | warning |
| `MUST_VISIT_MISSING` | 必去景点是否都已安排 | error |
| `DUPLICATE_PLACE` | 同一天是否有重复地点 | warning |
| `WALKING_LIMIT_EXCEEDED` | 日步行距离是否超限 | warning |
| `FOOD_AVOIDANCE_CONFLICT` | 餐厅是否与饮食禁忌冲突 | warning |
| `DAILY_END_TIME_EXCEEDED` | 最后一项结束时间是否超限 | warning |

## 七、关键约束提醒

| # | 约束 |
|---|------|
| 1 | 距离单位是**米**，时长单位是**分钟**，金额单位是**元**——不要搞混 |
| 2 | 坐标用 **GCJ-02**，顺序是 **`[经度, 纬度]`** |
| 3 | 地点统一用 **`place_id`** 关联，不要用地名 |
| 4 | **自动调整只做一次**，不要循环 |
| 5 | **局部重规划只能修改受影响的天/时段**，其余必须锁定 |
| 6 | **规则校验用 Python 写死**，大模型只用于生成调整策略和自然语言说明 |
| 7 | **所有修改都生成新版本**，通过 `parent_version` 链式关联 |
| 8 | 接口不得返回 API Key、完整 Prompt 或内部推理过程 |
| 9 | 高德失败时允许估算，但必须标记 `verified=false` |
| 10 | 没有有效 POI 或经纬度的地点不能进入正式行程 |
